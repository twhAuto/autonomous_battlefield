# Triage CI

1. Read `docs/developer/ci.md`, `docs/operations/jenkins.md`, and the failing run's exact branch, commit, PR target, stages, console output, and published checks. Identify both the PR head and target commit tested by the run, using the checkout or synthetic merge parents when applicable. Compare that pair with the current PR head and target tip before treating a prior green build as current evidence. A queued, aborted, or skipped stage is not a passing check. Jenkins PR verification only runs for targets `dev` or `main`; work-branch stack targets are skipped and require a build after retargeting to `dev`. A manual Sonar preview against an unmerged stack base is separate evidence; the next Jenkins preview resets the project against the new target.
2. Find the earliest actionable failure and classify it using evidence: code/test regression, threshold or scanner finding, agent/tool/credential problem, external service outage, or pipeline configuration. Inspect downstream failures for shared causes before choosing a fix. Never change coverage thresholds, suppress findings, or claim Sonar is clean from passing local tests.
3. Reproduce the smallest applicable check through the existing `scripts/test/` and `scripts/ci/` entry points; use `with-test-postgres.sh` for backend coverage and `test-deployment.sh` for deployment changes. If `test/boundaries` fails, a forbidden dependency means fixing the import, not the rule (change a rule only with user approval); a stale component map means regenerating `docs/developer/component-map.md` with the command in its failure message. For Sonar, read and follow [the SonarQube workflow](sonarqube.md) for server access, token handling, issue queries and the PR preview project; never scan unmerged code into the production project.
4. Fix the cause when within the task's scope. Rerun affected checks and inspect a new Jenkins/Sonar result when available. If the failure is environmental, document the failing dependency, evidence, owner/action, and whether a safe retry is warranted; do not disguise it as a source fix.
5. Report the failing run and head, first actionable error, diagnosis, change made, commands/results, and checks still pending or blocked. Do not equate a local reproduction with a green Jenkins gate.
