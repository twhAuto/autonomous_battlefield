# Raise a pull request

1. Apply the `AGENTS.md` branch, check, and review rules and read `docs/developer/cross-review.md`. Inspect the worktree, fetch the remote, confirm the branch was based on the latest `origin/dev` unless the user chose another base, and check the diff against that base. Preserve unrelated work; resolve an unexpected base or uncommitted changes before publishing.
2. Check that the diff matches the request, contains no secrets or generated debris, and updates affected docs. Run checks relevant to the changed files as specified by `AGENTS.md`; include `scripts/test/test-deployment.sh` for deployment changes. Record commands and actual results, distinguishing unavailable checks from passes.
3. Commit and push the intended changes. Open a **draft** PR targeting `dev` explicitly unless the user selected another target. Describe motivation, changes, risks, validation, and outstanding checks, following `.github/pull_request_template.md`. For ticketed work, read the linked Notion ticket, prefix the PR title with its ID (`AB-NN: concise change title`), and begin **Motivation** with a link containing the ID and exact current ticket name: `[AB-NN — Ticket name](NOTION_URL)`. Include each ticket when the PR covers more than one; keep these references current when updating the PR. If no ticket is associated, say so instead of inventing one. Always complete its **AI assistance** section as `docs/developer/ai-development-policy.md` requires: the tools and models used, the affected files or concerns, what the author validated independently, any uncertain or rejected suggestions, and whether the change touches an area that needs human approval. An attribution footer alone does not satisfy the policy. For `dev` to `main` promotion, use the release workflow instead.
4. For meaningful agent-authored changes, invoke the existing `scripts/review/cross-review.py` with `--author codex --pr NUMBER` or `--author claude --pr NUMBER`, according to the actual author. Follow the guide's evidence and response flow. Do not reproduce reviewer/model logic here, run on intermediate commits, or bypass its round limit. If the user explicitly skips cross-review for this PR, honor that instruction and record the omission in the handoff.
5. Verify findings before fixing them; rerun applicable checks and use at most one focused follow-up under the runner's limit. If review cannot complete, report why and leave unresolved work in draft. Never treat an advisory review as CI approval or merge/deploy authorization.
6. Report the PR URL, head, checks, review status, unresolved findings, and next step. A skill provides workflow instructions; select the author model in agent/CLI configuration, not in this file.
